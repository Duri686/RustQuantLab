# 🔍 UX 审计报告 — v0.2 完整交易终端

> **审计日期**: 2026-02-07
> **审计范围**: v0.2 已完成功能的用户体验
> **审计方法**: 基于 Nielsen 启发式评估 + 代码走查
> **目标用户**: 有一定交易经验的模拟交易学习者

---

## 总体评价

v0.2 在**功能完整性**上达到了专业交易终端标准（限价单、逐仓/全仓、风控四级、深度图），但在**可用性**和**新手引导**方面存在明显短板。核心问题集中在：缺乏引导流程、中英文混杂、风险信息层级不当。

### 评分摘要

| 维度 | 评分 | 说明 |
|------|:----:|------|
| 功能完整性 | ⭐⭐⭐⭐⭐ | 交易流程完整，风控引擎专业 |
| 视觉设计 | ⭐⭐⭐⭐ | Binance 对齐设计系统，暗色主题专业 |
| 操作反馈 | ⭐⭐⭐⭐ | ActionButtons 三态反馈、Toast 事件通知、骨架屏 |
| 响应式布局 | ⭐⭐⭐⭐ | Mobile BottomSheet + Desktop 侧边栏，断点策略清晰 |
| 新手引导 | ⭐ | 无任何引导流程、帮助文档、术语解释 |

## 🔴 P0 — 严重体验问题

### 1. 零引导体验 (Onboarding Absence)

**现状**: 用户首次进入直接面对复杂交易终端，无任何引导。

**代码证据**:
- `EmptyPositionState` 仅显示 "No active position / Open a Long or Short to start trading"
- 无 Tooltip 解释杠杆、保证金模式、强平价等核心概念
- 无新手教程、引导 Overlay、帮助入口

**影响**: 目标用户（交易学习者）在最需要帮助时得不到引导，学习曲线陡峭。

**建议**:
- [ ] 首次访问引导流程 (3-5 步 Tooltip Tour)
- [ ] 关键术语 Tooltip (杠杆、逐仓/全仓、强平价)
- [ ] "?" 帮助按钮链接到文档或内置帮助面板

### 2. 语言混杂 (Language Inconsistency)

**现状**: 界面中英文混用无规律，增加认知负荷。

| 区域 | 语言 | 示例 |
|------|------|------|
| 按钮文案 | English | "Buy / Long", "Close", "Add Margin" |
| 表单标签 | 中文 | "保证金模式", "限价单必须指定价格" |
| Toast 通知 | 中文 | "开仓成功: LONG 0.0100 BTC @ 95000.00" |
| 仓位状态 | English | "Long", "Short", "Safe", "Critical" |
| 统计面板 | English | "Mark Price", "Funding / Countdown" |
| 内部文案 | 混合 | "已平仓", "挂单", "距强平 X%" |

**建议**:
- [ ] 统一为中文优先（目标用户为中文用户），英文术语保留行业惯用语（Long/Short/USDT）
- [ ] 建立 UI 文案 Glossary，规范哪些术语保留英文

## 🟡 P1 — 中等体验问题

### 3. 风险信息视觉层级不足

**现状**:
- "距强平 XX%" 使用 9px 灰色字体，位于仓位卡片最底部 — 最关键的风险信息却是最不起眼的
- 风险等级仅用小 Badge 展示 (10px)，无进度条可视化
- Critical 状态用 `animate-pulse` 闪烁，持续时间长时体验刺眼

**建议**:
- [ ] 强平距离改为**进度条**可视化 (绿→黄→红)
- [ ] Critical 状态改用持续红色边框 + 一次性震动提醒，不用持续 pulse
- [ ] 保证金率使用颜色渐变仪表盘 (Gauge) 代替纯数字

### 4. 移动端交易体验粗糙

**现状**:
- 底部快捷 Buy/Sell 按钮硬编码 0.01 BTC — 用户无法自定义快捷下单数量
- BottomSheet 展开无视觉 affordance (用户不知道可以上滑)
- 移动端图表固定 60vh，订单簿仅 214px，信息层级失衡

**代码证据** (`TradePanel.tsx:673-686`):
```tsx
onPlaceOrder?.('LONG', 0.01, leverage, marginMode, 'market', undefined, currentPrice);
```

**建议**:
- [ ] 快捷下单数量可配置 (上次使用的数量 / 预设)
- [ ] BottomSheet 增加上滑指示器 (向上箭头动画)
- [ ] 移动端图表/订单簿高度比例可拖拽调整

### 5. 交易表单缺失关键交互

**现状**:
- 无 "Max" 按钮快捷填入最大可开仓量（需手动点 100% preset）
- 市价单输入框显示 "Market Price" 文本 — 样式上看像可编辑，实际 disabled
- 无市价单二次确认（仅高杠杆 >50x 有确认弹窗）
- 历史仓位硬编码显示最近 5 条 (`.slice(-5)`)

**建议**:
- [ ] Size 输入框旁增加 "Max" 快捷按钮
- [ ] 市价单价格区域改为非输入框的信息展示样式
- [ ] 历史仓位支持展开查看全部 + 按盈亏筛选

### 6. LIVE 模式交易不可用，无说明

**现状**: Binance 实时模式下整个交易面板隐藏，用户无任何提示理解原因。

**代码证据** (`App.tsx:511`):
```tsx
{dataSource === 'mock' && (
  <section className="hidden xl:block ...">
    <TradePanel ... />
  </section>
)}
```

**建议**:
- [ ] LIVE 模式下显示交易面板的 disabled 状态 + 说明文案 ("实时行情模式仅供观察，模拟交易请切换至 Mock 模式")
- [ ] 或在 Header 数据源切换旁增加提示 Badge

## 🟢 P2 — 轻微/优化级

### 7. 信息密度过高

- 仓位卡片使用 10px/9px 字体，数据网格 6 个字段挤在小空间
- OrderBook 行高紧凑，Ticker 区域用 8px 标签
- 无字体大小调整选项

**建议**:
- [ ] 提供「紧凑/标准/舒适」三档信息密度切换

### 8. 无障碍 (Accessibility) 缺失

- 交互元素缺少 `aria-label` (ViewModeButton, ActionButtons)
- 风险等级仅靠颜色区分，色盲用户无法识别
- 部分触摸目标 < 44x44px (OrderBook 行、StatsPanel 单元)

**建议**:
- [ ] 关键按钮添加 `aria-label`
- [ ] 风险等级增加图标辅助 (✓/⚠/⛔)
- [ ] 确保所有可点击元素 ≥ 44x44px

### 9. 缺少音效反馈

- 开仓/平仓/强平等关键事件仅有 Toast 视觉反馈
- 无声音提醒选项（交易所标配）

**建议**:
- [ ] 可选的交易音效 (开仓成功/强平警告/限价单成交)

### 10. 账户操作无安全网

- 账户重置 (resetBalance) 无确认弹窗，一键清零
- 平仓按钮 "Close" 太小且无二次确认
- 无撤销最近操作能力

**建议**:
- [ ] 账户重置增加确认弹窗
- [ ] 平仓增加滑动确认 (Swipe to Confirm) 或二次确认

## ✅ 做得好的地方

| 功能 | 评价 |
|------|------|
| **ActionButtons 三态反馈** | Loading → Success ✓ / Error shake，符合反馈原则 |
| **高杠杆确认弹窗** | >50x 杠杆时弹出确认，防误操作 |
| **数据源切换过渡** | 骨架屏 + 最小展示时长 + 触觉振动，体验流畅 |
| **限价单偏差提示** | 实时显示 "低于/高于市价 X%"，辅助决策 |
| **PositionContext Banner** | 有持仓时提示加仓行为，减少误解 |
| **逐仓追加保证金** | 内联输入设计，无需弹窗跳转 |
| **Desktop/Mobile 自适应** | BottomSheet + 侧边栏双形态，共享 formContent |
